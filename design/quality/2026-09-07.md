# Engineering quality review — 7 September 2026

## Scope and baseline

Reviewed the Python dictation boundary, local audio/model resource handling,
Swift source collection, capture persistence, inbox concurrency, runtime request
validation, QA storage isolation, and test execution/evidence. Changes preserve
the current product flows; no app installation, live-data migration, or product
redesign is part of this work.

The frozen original revision `ca2bc19f24e43709b6cb7101b14753777ea92a59` passed `scripts/test-agent-harness.sh --unit` in
**418.83 seconds**. Its backend suite had **9 tests**. A green baseline did not
detect the failures below; each implementation defect was reproduced with a
new regression before its fix. The old evidence output also overstated which
suites had actually run.

## Validation

Targeted backend, inbox, paths, source collection, Sources UI, capture storage,
Codex app-server/runtime, Claude Code runtime, and OpenCode HTTP checks pass.
The backend suite now contains **22 tests** and runs in approximately **0.6
seconds**. Independent reviewers checked the backend/capture and inbox/isolation
changes against their call sites.

The harness itself has **8 test methods covering 15 CLI/isolation/failure
scenarios**, and evidence validation has **12 regression tests**. The final
live gate requires the **46 unit suites/checks plus 6 live suites/checks**.

A targeted Codex live smoke passed in **42.21 seconds**, covering discovery,
authentication, new turns, resume identity, image input, interruption, and
descendant cleanup. Its shared canary returned the expected text with zero
errors in **7.98 seconds**.

The final combined `scripts/test-agent-harness.sh --live` gate **passed in
730.05 seconds** on the complete changed tree. It produced **52 successful
suite/check receipts** (46 unit and 6 live), backing **91 registry checks**.
Both release and QA app builds passed, including the release QA-symbol check.
The final fresh-root OpenCode text/tool/skill/image/permission/cancellation
smoke passed in **62 seconds**, its supervisor checks in **3 seconds**, and
the Codex discovery/auth/new/resume/image/interruption smoke in **44 seconds**.
The shared runtime canary matched. OpenCode uses the real pinned runtime with
a controlled provider fixture; Codex uses the installed authenticated runtime.

Saved results: [execution log](2026-09-07-live.log) and
[validated evidence](2026-09-07-live-evidence.json). Evidence records the
uncommitted source fingerprint and was validated against the unchanged
implementation after the run. The catalog contains 161 capabilities across
22 areas; its full 164-entry registry includes higher-tier checks that this
live run does not claim.

The three-second targeted command measures the cost of checking one suite,
not a speedup of the full gate. The original unit timing and final live timing
cover different work and are not a performance comparison. Changes remain
uncommitted; the installed daily-use app was not replaced.

## Remaining work and limits

|---|---|---|
| Source cancellation resolves callers immediately, but an in-flight HTTP request can occupy a worker slot until its bounded timeout. | Known remaining limitation. | Add cancellable transport ownership if rapid source switching proves consequential. |
| Synchronous capture return values are provisional; only the finalization callback guarantees persistence. | Existing direct-delivery contract retained. | Coordinate any change with capture routing and UI error handling. |
| Local MLX direct-array transcription does not explicitly pass its sample rate. | Requires model-specific verification. | Test installed model behavior before changing resampling. |
| Budget-blocked jobs are not automatically reconsidered at midnight. | Recovery policy requires a product decision. | Decide whether the next budget period should resume blocked jobs automatically. |
| A successful executor result may race supervisor shutdown. | Inspection concern; no deterministic reproduction. | Build a reliable race fixture before changing job state transitions. |
| Signed-app interaction and multi-hour soak. | Not run during this review. | Run the existing E2E/release tiers for those additional guarantees. |

Further broad changes should be driven by these findings or measured hot paths.
The review does not establish that every subsystem is bug-free or that the
capability catalog measures code coverage.
