# UI/UX audit — 7 September 2026

## Product direction

Preserve the existing workspace and improve the reliability of everyday
interaction. The installed app has a persistent Now, Inbox, Threads, Data,
Assistants, Automations, Speech, and Settings sidebar.

Governing principles:

- An update must preserve what the user is writing, their selection, and focus.
- Navigation may change the view; saving must be explicit and keep conflict checks.
- Every clickable primary action must also work with keyboard and accessibility tools.
- Validation and status should explain what happened where the user acted.
- Narrow layouts must keep the composer, its actions, and source forms usable.

A broader navigation redesign and richer multi-line cards were considered.
The current workspace already provides clear destinations, so this audit keeps
that structure and addresses concrete interaction failures first.

## Decision branches

| Branch | User job and decisions | Acceptance evidence |
|---|---|---|
| Navigation and rows | Open a thread or setup object; individual accessible actions, keyboard activation, visible focus, full labels for truncated titles. | Native accessibility inspection and action tests. |
| Composer and attachments | Edit and send to the intended thread; selection across refresh, Unicode offsets, attachment destination, narrow and overflowing controls. | AppKit interaction/state tests and representative layout inspection. |
| Setup editors | Retune assistants/system agents and create automations; independent drafts, explicit save, revision conflicts, dependent controls, focus and validation. | Refresh/navigation/save/conflict regressions with isolated data. |
| Data | Find, connect, inspect, and configure sources; stable filtering, visible validation, honest unsaved status, back position, built-in controls. | Source UI regressions and native visual inspection. |
| Settings and Speech | Find settings sections and understand the speech input; avoid duplicate headings, keep native controls aligned with the workspace palette, label editable controls. | Inspection of the installed app and rebuilt surfaces. |

The composer keeps one control row when space permits. Below 780 points it
moves runtime, model, and reasoning choices to a second row, leaving access,
capture, activity, and Send/Stop together. This preserves more message space
on wide views than an always-two-row layout. Horizontal attachment scrolling
keeps image collections bounded without an indefinitely growing grid.

## Findings

| Area | Improvement | Evidence |
|---|---|---|
| Agent rows | Each actionable row exposes its full name as an accessible button, supports Return/Space, and draws keyboard focus. Read-only run history remains non-interactive. | The baseline exposed rows as a single static text block; the new native action regression passes. |
| Composer state | Same-thread refresh retains the actual editor, selected text, undo history, and exact failed-send draft. | AppKit identity, selection, undo, rejected-send, and thread-deletion checks. |
| Unicode | Focusing puts the caret after the full draft. | The emoji fixture previously used offset 7 instead of UTF-16 offset 13. |
| Attachments | A delayed picker stays with its original thread. Many attachments scroll without stretching the panel. | Two-thread navigation plus 15-attachment scrolling/removal checks. |
| Composer controls | Empty Send is disabled; narrow layouts preserve readable choices, activity, Stop, and the full access-mode label. | Layout checks from 420 to 900 points; the previous 520-point layout reduced activity to 4 points. |
| Source filtering | Results update around the mounted search field; empty results explain the filter outcome. | Field identity, keyboard focus, and selection survive filtering. |
| Source validation | Untouched forms validate, errors appear beside the action, and inputs stay intact. | Baseline blank Connect was a no-op; invalid save preserves the actual editor and selection. |
| Source feedback | Editing after Save shows unsaved state; reverting clears the draft. Built-ins omit irrelevant connection fields. | Save/edit/revert/external-update and built-in control regressions. |
| Source navigation | Back restores reading position and clamps shorter content; returning to inventory starts at the top. | An 80-item list restores its position. A baseline deep-form return produced a blank inventory; the regression now passes. |
| Setup drafts | System-agent settings survive refresh and Test now. Core, Ledger, skills, settings, and creation forms preserve independent edits. | Refresh, tab-switching, independent-save, and fresh-creation scenarios. |
| Conflict recovery | Dirty settings/memory retain their original revision, and Reload saved provides explicit recovery. Clean fields reveal external changes. | External-update conflict and recovery scenarios retain user drafts. |
| Dependent controls | Restored runtime/trigger/source choices also update enabled fields and explanatory text. | Daily scheduling and review-copies restoration checks. |
| Form access | Fields have semantic labels; same-form refresh preserves focus, text selection, and scroll. | Native field-editor tests and 470/700-point form inspection. |
| Save errors | A new or repeated save failure scrolls into view once; later background refreshes preserve reading position. | The baseline left an error outside the viewport. The regression verifies visible failure, retained draft, and stable subsequent scrolling. |
| Settings | The embedded page uses the workspace heading, hides the redundant picker caption, and adopts the workspace accent and background. | Fewer duplicate labels and more vertical room for controls. |
| Speech | The empty surface explains where to enter text; voice, speed, style, playback position, and text input have accessible names. | The API diagnostic remains available as help on the instruction line. |

## Verification and delivery

The final combined `workspace_ui` suite passed after a 41-second build and 2-second
test run. The final integrated `--unit` gate then passed in **540.49 seconds**:
47 executed suites, 80 registered checks backed by execution receipts, both
release and QA app builds, and the complete 162-capability catalog validation.
The source UI and workspace UI regressions passed inside that gate.
See the [unit run log](2026-09-07-ui-unit.log) and
[execution evidence](2026-09-07-ui-unit-evidence.json). The evidence records
the tested source fingerprint before commit; it is historical proof for that
source state, rather than a claim about later revisions.

Representative AppKit renders were inspected at 420–900 points for the
composer, 470/700 points for automation forms, and 380 points for source forms.
The prior reliability batch
was committed and pushed as `eb09ea9`, installed with a stable Developer ID
signature, and relaunched successfully before this audit.

This review preserves explicit saves and the existing navigation model. It
does not claim a full VoiceOver audit, signed-app E2E coverage, or multi-hour
soak testing. Automatic speech playback, permission policy, dictation routing,
and provider runtimes remain outside these UI changes.
