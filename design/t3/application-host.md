# Native application composition

The final path is explicitly selectable in an isolated QA build with `VOICE_FLOW_NATIVE_SHELL=t3`. The first executable QA guard still validates `VOICE_FLOW_CONFIG_ROOT` and non-daily ports before paths, logging, AppKit or singletons. Daily builds ignore this selector. This commit does not install, launch or activate the path.

`AppDelegate` starts native recording, capture, watcher, TTS, derived captured-data indexing and settings, then `T3ApplicationHost`. The selected path does not instantiate `AgentSession`, `AgentSupervisor`, `NextQueue`, the old canonical thread DB or the legacy public MCP execution/session registry. Existing dictation/TTS/history/Data services remain available; the old panel exposes only these native services and routes thread navigation to T3. Old QA execution routes return409 on the T3 path; authenticated QA state reports the actual selected owner and native shell state.

The host verifies the sealed bundled T3 archive, starts its existing environment process with private stdin bootstrap, mounts the official Swift MCP service on the existing private native broker, then authenticates the matching WKWebView using the native cookie bootstrap. The renderer receives no provider credentials or native gateway configuration. Native tools use actual screen/capture/overlay handles, frozen manifest/config revisions, the current account checkpoint and existing permission policy. Overlays render only for the current published T3 thread. Native actions reuse source custody and existing recorder/STT/TTS callbacks; no model send originates from those callbacks.

Local launch does not connect to an account. The account owner and runtime lease are resolved lazily through the one existing CloudSyncController/CloudHTTPClient. Settings queries actual `/me/homes/continuable` and permits explicit selection only of the current Mac's `serving` home. No create/takeover is performed, and sync transport never implies an execution destination. The selected origin/owner/device/home is stored in existing `cloud-sync-account.json`, with no token. Sign-out/account changes preserve that selection for local history but remove its execution authority. Choosing another home creates a separate namespace; no data migration or silent rebind occurs.

Each selected home uses `<isolated-root>/t3-environments/<sha256(origin,owner,home)>/home` (or `local` before selection). `native-location.json` retains the OS-selected loopback port and dedicated WebKit store UUID. A later port conflict or corrupt location file refuses startup; it never silently moves drafts to a fresh browser origin. Existing source stores remain under their native owners. Pending input does not automatically replay after reconnect.

Account, child or policy changes synchronously revoke native checkpoints and broker capability. After readiness, the exact captured native-bootstrap child receives SIGUSR2 once to cancel admitted runtime work while preserving local history. Native bootstrap requires the sealed archive receipt to declare `nativeAuthorityRevocation: "sigusr2-v1"`; older or unmarked artifacts refuse startup before a child is spawned. The release owner must add this marker only after verifying the matching rebuilt server handler. Local history/drafts remain available; explicit Settings reconnect creates a fresh host at the same home/origin. Rapid reconnects drain the previous launch chain first. AppKit termination returns `.terminateLater`, awaits broker/tools/owned child teardown without blocking MainActor, then replies to the termination request. No PID from untrusted disk state is killed.

Validation: focused filesystem/selection/drain tests and native SDK configuration/revocation tests; whole production-source typecheck with QA selector. No GUI, Keychain, live account/home selection, real screen/control, paid model or full optimized app build was run for this branch. Parent integration must supply the matching rebuilt T3 artifact, validate bootstrap without an account, then perform the single coordinated WK/native input/account/quit acceptance. Existing imported history, retained-source recovery UI and final daily cutover remain separate preservation gates.
