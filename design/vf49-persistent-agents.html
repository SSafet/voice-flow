VF-49 — persistent assistants: named specialists that survive

Everything here is derived from what shipped and retained users — sources in amber italics; the evidence base is research/vf49-persistent-agents-landscape.md (43 products, 6 clusters). The one-line model: an assistant is a folder of markdown — addressed by name, scoped by allowlist, remembered in files you can open, run as fresh sessions, reporting into the same pill you already read with VF-48's player and consumption.

0 · What is borrowed from where

ComponentBorrowed fromThe rule
DefinitionClaude Code subagents · Copilot agents · custom GPTsOne markdown file per assistant: name + description + instructions + tool allowlist + model. The files ARE the agent; fresh stateless sessions at invocation. (OpenAI just killed its stateful Assistants API — persistence lives in data.)

TriggersChatGPT Tasks · Scheduled Devins · OpenClaw HEARTBEAT.mdPlain-language schedules + event triggers, run INCREMENTALLY (run N+1 reads run N's notes). Local runner = the VF app itself (it already runs the watcher); missed runs queue to next wake.
ReportingChatGPT Pulse · Zapier All Activity · DustResults land as pushes in the pill/panel — a pull surface with VF-48 consumption. Asks pause the run and pulse the ring. A triggered assistant NEVER opens audio or takes the screen.
ScopeZapier's single-purpose split · Dust's 300k small agents · DevinOne assistant = one bounded recurring workflow with a checkable output. Few assistants, legible ones. Persona stays thin — named capability, not named personality (Alexa celebrity personas, Dot, Friend all died).

1 · An assistant is a folder — the whole definition, readable in one screen

description: family meals & nutrition. Route me

tools: notion (Food DB, Meals page), web-search
sources:
  - notion:nutrition-kb   # when: any food/menu question
  - dictations           # when: told "as I said"
triggers:
  - "Sunday 18:00 — draft next week's family menu"
autonomy: ask-first      # acts only after confirmation
voice: shimmer          # her sound in the player
model: default
---
You are the family nutritionist. Approaches and foods
come ONLY from the approved-by-nutriciologist pages in
the knowledge base — never invent regimes. Age bands:
6–12m, 12–24m, toddlers, adults. Prefer BG-seasonal
ingredients. Flag any conflict with the approved list
instead of resolving it yourself.
name + description — the description doubles as the routing trigger, exactly like Claude Code subagents' frontmatter. Copilot's .github/agents/*.md is the same shape.
tools / sources — default-deny allowlist; each source carries a "when to use" clause. Manus Knowledge: Name + When-to-Use + Content + toggle. Home Assistant: per-assistant entity exposure.
triggers — plain language, no cron UI; the run is incremental (reads its own last notes). Scheduled Devins, OpenClaw HEARTBEAT.md.
autonomy — per-assistant dial: ask-first vs act-with-receipts. Lindy's Ask-for-Confirmation flag; Manus's front-loaded questions.
the body — thin strategy core, always loaded. Procedures live next door in procedures/*.md, fetched on demand. Skills' progressive disclosure.
memory/ — core.md (capped, always in context), topic files, ledger.md. You can open and edit any of them — trust requires it. Letta's MemFS pivot; the #1 complaint against ChatGPT/Cursor invisible memory.

4 · Memory you can open

assistants/nutra/memory/core.md  ·  capped ~200 lines, always loaded
## The family
- toddler (14m): no honey, dairy OK — confirmed 2026-06-12
- Safet: cutting, ~2300 kcal weekdays  (stated 2026-07-02)

## Standing rules
- fish twice a week; BG-seasonal veg preferred
- NEVER suggest regimes outside the approved KB pages

## Superseded
- ~~2000 kcal target~~ → 2300, changed 2026-07-02
Written by the assistant, readable by you. Every fact is date-stamped; a change supersedes, never silently overwrites. Zep's became-true/stopped-being-true, as a cheap file convention.
Nightly consolidation. The 21:37 pass extends per-assistant: dedupe, resolve contradictions, expire stale facts, promote repeated observations into the core. Letta sleep-time · OpenAI Dreaming V3 · your watcher ledger — three independent convergences.
Isolation. Nutra never reads Scribe's memory. Sharing is an explicit line in the definition. ChatGPT Projects' fenced memory — shipped because users demanded it.
The global layer. Facts about YOU (SAFET.md-style) sit above all assistants; per-assistant memory overrides it locally. Its update path is an open decision below.

8 · Open decisions — needs your call

1 · Name routing rules. Leading name only (like FLORA today)? What do NO-NAME captures do — current behavior unchanged (visible conversation / frozen route), FLORA stays the general assistant? Recommend: exactly that; plus a misroute fix-up: re-dictate with the right name, and the wrong assistant's turn is cancelled. No product has voice-name routing in a dictation stream — this is ours to define.
2 · Picker slots. Assistants claim ⌃⌥ numbers like sessions, or stay on ≋ dots + panel + voice addressing? Recommend: ≋ dots only when active (mock §2); numbers stay with ephemeral sessions. Alternative: pin ⌃⌥7–9 to three assistants.
3 · The roster. Watcher / Scribe / Librarian / Nutra proposed — which first, which names? Recommend: start with Watcher (exists, just gets named) + Scribe (highest daily value), add the rest after a week of retention on those two.
4 · Global layer precedence. Does per-assistant memory override the SAFET.md-style layer? Can an assistant PROPOSE a global-layer change? Recommend: local overrides global; global-layer edits are suggest-then-approve only (Devin's Knowledge model).
5 · Autonomy default. Per-assistant dial exists — but what's the default for a NEW assistant? Recommend: ask-first; you promote to act-with-receipts per assistant after trust builds (the evidence: gates are what make autonomy usable).
6 · May a triggered assistant ever speak first? Home Assistant's Ask-Question is liked; Friend's interjections are hated; your law is audio-never-auto-plays. Recommend: never — pull surface only, forever. (Saying yes later is easy; un-saying it isn't.)
7 · Memory write path. Agent-edited visible files with consolidation receipts (recommended), or suggest-then-approve for every write? Recommend: direct writes for the assistant's own files + receipts; approval only for the global layer (decision 4). Silent pipeline extraction is the documented trust-killer — never that.
8 · Local-only triggers. Accept queue-on-wake semantics (missed schedule runs when the Mac wakes, with a receipt), keeping the pure local-first story? Recommend: yes — cloud runners trade away the differentiator; the LaunchAgent nightly already proves local works for your rhythm.
9 · Backend for background runs. Headless Claude Code (like the nightly review — proven, skills/MCP-native) vs codex exec (your interactive default)? Recommend: Claude Code for triggered runs, whatever the panel conversation already uses for addressed turns.

9 · Engineering notes (for the implementation tickets)

· Seams that already exist: AssistantWakeMatcher (N names is a loop over the same matcher); AssistantHistoryStore (per-assistant conversations = one store per assistant or a scoped id); codexPreamble / systemPrompt builders (inject composed definition); LaunchAgent + ANALYZE.md (the background-run template); MessageInbox + deliverPush (reporting); MCP tool registry (source scoping).

· New pieces: the assistants/ folder format + loader; the in-app scheduler (timer + queue-on-wake + caps + receipts); allowlist enforcement on the composed session; Settings → Assistants tab; per-assistant memory lint appended to the nightly pass; ≋ rows/dots in panel and picker.

· Order of build (one vertical slice first): folder format + loader → name routing (N wake words) → panel rows → THEN the scheduler → THEN memory consolidation. Watcher-as-first-assistant exercises the whole pipeline with zero new risk surface (it already runs nightly).

· Security floor from day one: default-deny tools, no third-party assistant definitions, run caps, kill switches, every background artifact inventoried in Settings (surface-invisible-systems).
