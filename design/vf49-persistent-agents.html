VF-49 — the persistent assistant: FLORA that survives

Everything here is derived from what shipped and retained users — sources in amber italics; the evidence base is research/vf49-persistent-agents-landscape.md (43 products, 6 clusters). The one-line model: an assistant is a folder of markdown — addressed by name, scoped by allowlist, remembered in files you can open, run as fresh sessions, reporting into the same pill you already read with VF-48's player and consumption. Roster decision: FLORA only — the model supports more, but exactly one exists.
FINAL SCOPE (Safet, 2026-07-29): the deliverable is the STRUCTURE — FLORA's folder (definition + memory + her own named workspace she works in), replicable by copying the folder: a future specialist is a variation extending FLORA with a compound wake word ("FLORA watcher"), its own name and its own workspace. OUT of scope, by decision: triggers, background runs, autonomy changes (she keeps her current near-full access), and any global memory layer. The structure leaves room for triggers later, set by Safet whenever he decides.

The definition — what makes an agent "persistent". An agent is persistent when it survives the conversation: quit the app, come back in a week, and it still knows four things —
1 · WHO it is — a stable name and address whose identity outlives every session (you talk to "the same FLORA", however many sessions ran in between).
2 · WHAT it knows — memory that accumulates across interactions and is curated (consolidated, deduped, superseded) — not transcript scrollback. What you tell it today shapes its answer next month.
3 · WHAT it's for — standing instructions, tools, and data sources that never need restating: its job description is authored once and evolves, instead of being re-explained per chat.
4 · WHAT it was doing — standing intentions: triggers whose runs continue incrementally (run N+1 reads run N's notes) instead of starting from zero.
Persistence lives in data — the folder — never in a running process; sessions stay cheap and disposable. And it is NOT: a persona (those died), a daemon, or open-ended autonomy (that failed everywhere). Today's FLORA has 1 and conversation-resume; VF-49 gives her 2, 3 as files you can open, and 4. This is Altman's "constantly running proactive AI over your context" made concrete by what actually shipped: identity + curated memory + standing scope + incremental triggers.

memory/ — core.md (capped, always in context), topic files, ledger.md. You can open and edit any of them — trust requires it. Letta's MemFS pivot; the #1 complaint against ChatGPT/Cursor invisible memory.
