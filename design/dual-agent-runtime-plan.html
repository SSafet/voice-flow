Voice Flow · final architecture plan

One harness. Two runtimes. Durable agents.

Keep Codex CLI, add OpenCode, and let each conversation switch safely. Voice Flow remains the owner of history, tools, memory, skills, permissions, credentials, jobs, and every user-facing effect.

Release gate

FIRST SLICE
OpenCode text + image + Voice Flow screenshot tool, then OpenCode → Codex → OpenCode on one canonical transcript, including a mid-stream process kill and clean recovery.
NO LOST STATE
Each user/final message exists exactly once. Dirty bindings always reseed. Public MCP registry remains untouched by embedded tools.
NO SECRET LEAK
Canary provider key absent from config, logs, SQLite, generated files, screenshots, and child process environments.
EVERY CAPABILITY
Capability catalog has a test owner and evidence. Changed paths get full E2E; adjacent dictation, pill, TTS, MCP, watcher and sync paths get signed-app regression.
ROLLBACK
OpenCode defaults off at first. Stop its supervisor, choose Codex, reseed from canonical history, and continue without transcript or memory conversion.
