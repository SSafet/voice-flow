# Captured query and retrieval integration

This S2 slice makes the derived captured index readable through one service. It does not introduce a server or a second canonical store. It starts at S1 `adba148` and is intended for the platform integration checkout, never the daily app.

## Scope and adoption decision

The governing [captured-data design](../../atika/docs/architecture/platform/07-captured-data-and-annotations.md) and [reuse gate](../../atika/docs/architecture/platform/13-capability-alignment-and-reuse.md) remain authoritative. The draft S2 checkout contains proposed tests, not a query implementation; no old runtime, generated contract or dependency state was taken from that branch.

- **Data / generated, Access + Efficacy / tools:** keep GRDB **7.11.1** with system SQLite FTS5, already pinned in `Package.resolved`. Use one read snapshot for each query, parameterized filters and GRDB's FTS pattern builder. The only store change exposes its existing row decoder inside the module. No migration or index writer is added.
- **Consumption / Control:** query results use the existing generated contracts. Search, get, frames, around and summary all share this implementation for tools and the owner interface. Day summaries use native Calendar so a daylight-saving day may contain 23 or 25 hours. Counts and search are SQL; clipped calendar buckets are folded in Swift because an explicit device time zone and repeated-hour offsets must survive. This is a deliberate correction to a start-time-only grouping, not a second index.
- **Input / Output:** ImageIO performs native thumbnail decoding and orientation handling; the existing `ImageUtils.jpeg` handles pixel dimensions and encoding. Originals are read through no-follow directory descriptors and never rewritten. Only local tool derivatives are written, with exclusive file creation under `captures/derived`.
- **Infra / connectivity, Access + Efficacy / connectors:** choose the **official Swift MCP SDK** for the native tool-host migration, or the already-supported TypeScript SDK if the tool owner is the adopted T3 environment. Captured retrieval needs neither a custom MCP parser nor a second server. This slice has no new package dependency or tool registration.

The official [Swift SDK](https://github.com/modelcontextprotocol/swift-sdk/tree/a0ae212ebf6eab5f754c3129608bc5557637e605) was inspected and tested at `a0ae212ebf6eab5f754c3129608bc5557637e605` on 22 September 2026. Its [version negotiation](https://github.com/modelcontextprotocol/swift-sdk/blob/a0ae212ebf6eab5f754c3129608bc5557637e605/Sources/MCP/Base/Versioning.swift) retains a client's supported `2025-06-18` request. Its [tool result types](https://github.com/modelcontextprotocol/swift-sdk/blob/a0ae212ebf6eab5f754c3129608bc5557637e605/Sources/MCP/Server/Tools.swift) carry `structuredContent`, image metadata and named error status. The framework-neutral stateful HTTP transport supports sessions/SSE/replay and the server handles cancellation. GRDB and this SDK are MIT-licensed; native frameworks are supplied by macOS. Platform integration owns SDK pinning, attribution and updates when the single host is migrated.

The existing `MCPServer.callTool` returns only text plus an error bit. It can carry the local JSON reply through a thin callback, but it cannot represent the required structured result and device image blocks. Expanding that handwritten protocol is therefore not the chosen final adapter. The existing native host should migrate once to the SDK under V6/L6; the captured handler itself needs no lifecycle changes.

## Consumer interface

Construct `CapturedQuery(index:root:timeZone:indexProgress:mayRead:)`. `mayRead` defaults **false**: inject the current observe decision, including revocation. A query object is not an authentication credential. Do not cache a positive decision longer than the existing permission system permits.

`CapturedReadService.read(operation:arguments:limits:delivery:)` accepts a `CapturedReadOperation` and encoded generated input; it returns `CapturedReadReply(json:pictures:isError:)`. This is an application dispatch boundary, not JSON-RPC. The five operation names match the generated tool contracts.

- Owner client: `.interface` limits and `.metadataOnly`. A get ignores the picture request while reporting truthful picture state. Fetch `query.picture` separately over the authenticated byte channel; use `maxPx` for a thumbnail. `originalPicture` returns exact source image bytes for the authenticated owner interface.
- Tool on the Mac: `.agent` limits and `.localFiles`. The reply contains a disposable, bounded picture path and no image blocks. The existing derivative sweep must remove these after a day.
- Device tool: `.agent` and `.imageBytes`. The JSON contains no picture paths; pair each returned image with its id. Map the JSON to SDK `structuredContent` and the first text block; append images in order with `_meta["ai.atika/captureId"]`. Preserve the current negotiated revision and existing caller/thread identity.
- `query.day` produces the same hourly summary for a calendar day. `query.status` reports query-owned index progress and current source availability. `query.sourceStatus` distinguishes available, missing, thinned, deleted and indexed-text-only without mutating history. A removed pending WAV is counted as missing, never inferred to be still undelivered from stale extra JSON.

The read service reuses existing generated contracts; schemas, tool registration, grants, authenticated routing and full `TPCapturedHealth` assembly belong to the host. Full health needs real watcher, pending queue, sync and retention state; this service deliberately does not manufacture them. Recording download/retry, deletion/cleanup, text attachment packaging, drawing and the OCR worker remain with their owning packages. Stored OCR text is searchable now; no new collection or background recognition is started here. Legacy rows without indexed image dimensions report zero in metadata; decoded picture replies carry the actual dimensions, and the client should use intrinsic image geometry.

## Behavior and limits

Search uses literal all-prefix FTS patterns and deterministic rank/time/id ordering. Title weight is 2 and other fields 1: this implements the design's “title weighted double”; the old brief's zero weights would discard relevance for every non-title field. Collapse applies only to frames in the same activity span, preserving bundle frames. Search cursors count returned collapsed hits. Get keeps marks, child ids, links and context, with bounded text continuation. Long strings are redacted before windows/highlighting so a credential cannot evade the scrubber by straddling a boundary.

Private flags in row extra or context, skipped-private OCR, password manager identity, and descendants of excluded rows are filtered inside each snapshot. They are absent even when the caller knows an id. This does not claim better live Safari/private-window detection; that collection capability remains unchanged by S2.

Agent replies are limited to 12,000 JSON bytes, not characters; image replies are at most 12 images, 400,000 bytes each and 4,800,000 total. Source reads reject symlinks, traversal, non-regular files and sources over 64 MB. Thumbnail dimensions are bounded. Image failures retain indexed text. A vanished file does not resurrect because the cached row says present. Summary ranges clip spanning intervals before summing and split at real calendar boundaries. Historical pause records have no timestamps; only pauses whose owning span is fully included can be counted without inventing placement.

## Acceptance and remaining integration

The focused test runner compiles all production captured sources, generated contracts, and the existing secret policy and ImageUtils after their byte-identical extraction from platform commit `805e9a3`. The local dependency commit is `9de9787`; platform already has that extraction, so integrate only the query and evidence commits. Only unrelated UI collaborators are stubs. All fixtures are synthetic under a fresh temporary config root; no live watcher, screen capture, model API or daily data is used. `sdk-probe.sh` can then wrap an actual service reply using the pinned official SDK and run its compatibility tests. Execution receipts are recorded after the final source freeze.

The remaining running-system gate belongs to platform integration: authenticated owner routes and SDK tool registration must use this same service, show original/thumbnail/missing/private/denied states in the shared client, and preserve grants and image attribution over the actual device channel. Recheck cancellation, reconnect and the current clients' long-held ask/wait interactions through the existing native host before replacing it. The SDK tests establish component fit; they do not establish that app cutover. Root runs the combined signed app build/gate; this branch intentionally avoids another competing optimized app build.
