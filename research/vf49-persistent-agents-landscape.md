# VF-49 — Persistent agents: product landscape research

Produced 2026-07-29 by a 7-agent research sweep over shipped products, July 2026 sources. This is the evidence base for VF-49 — introducing persistent named specialist assistants into Voice Flow (today: one in-app assistant with the FLORA wake word) — and the spec is derived from it. Six clusters; for each, the per-product mechanisms that matter, then the cluster's condensed takeaways. Everything here traces to a shipped product, a dated announcement, or documented user reception.

## 1 · OpenAI ecosystem (ChatGPT consumer surface + developer platform)

**Custom GPTs + GPT Store (@-mentions)** — shipped Nov 2023 / store Jan 2024; consumer store effectively abandoned (pivoted to ChatGPT Apps, DevDay Oct 2025), but internal/enterprise GPTs thrive: usage grew 19x in 2025, ~20% of enterprise ChatGPT messages, BBVA alone runs 4,000+ internal GPTs. Specialist = config, not code: instructions field + knowledge files (~20 cap, RAG'd) + Actions (OpenAPI + auth) + capability toggles. Typing `@` mid-conversation swaps in another GPT's full config for that turn while keeping the shared conversation context (only previously-used GPTs are mentionable). Per-GPT tool scoping with per-domain consent on first Action call. No per-GPT memory (known gap); user-initiated only — Scheduled Tasks explicitly cannot run a custom GPT. Recurring complaints: knowledge files only consulted when explicitly asked; @-mentions intermittently broken on newer models.

**ChatGPT Memory (saved memories + reference chat history + Dreaming V3)** — saved memories 2024; reference chat history Apr 10 2025; free tier Jun 3 2025; Dreaming V3 Jun 4 2026. Three layers: (1) saved memories — explicit, user-viewable/editable/deletable fact list; (2) reference chat history — implicit recall over all past conversations, NOT auditable; (3) Dreaming V3 — background consolidation during account-idle compute that rewrites years of chats into weighted "memory chains", auto-revising stale facts (claimed recall 41.5%→82.8% at 5x less compute). Controls: independent layer toggles, per-memory delete, Temporary Chat bypass, in-UI "Updated saved memories" announcements. Loudest criticism targets the uninspectable layer: Willison's "memory dossier" (May 21 2025); TechTimes (Jun 5 2026) — Dreaming "limits the audit trail".

**ChatGPT Tasks** — beta Jan 2025, GA through 2025; a checkbox feature. Cron-like scheduled prompts (max once/hour), created conversationally, editable in a Tasks manager; "monitoring" tasks notify only on change and remember previous runs. Tasks run as plain ChatGPT — custom GPTs, voice, and file uploads unsupported: specialists and triggers were never joined. Caps 3–15 active tasks by plan. Universal critique: Tasks NOTIFIES rather than ACTS — the acknowledged white space.

**ChatGPT Pulse** — preview Sep 25 2025, mobile-first for Pro. Once daily, overnight, asynchronous background research produces 5–10 scannable topic cards — a feed the user opens on their schedule, never an interruption; cards expire unless kept. Inputs: chat history + Memory; connectors (Gmail, Calendar) OFF by default, removable. Steerable via "curate" + thumbs feedback; "allow proactive activity" master toggle. Reception: praised as proactive-without-interrupting; HN called AI-initiated messaging "obnoxious"; the extracted lesson — proactive output must be a pull-surface digest with opt-in data sources.

**ChatGPT Projects** — Dec 2024; project-only memory Aug 22 2025; free Sep 4 2025. Project-scoped memory: chats inside a project remember each other and cannot reference (or be seen by) conversations outside it. Per-project custom instructions override globals; per-project file sets (5/25/40 by plan) as standing knowledge. No triggers. The memory scoping was a requested feature ("limit ChatGPT memory to a single project"); users describe instructions+files+scoped-memory as "the underrated power" — a poor-man's persistent specialist.

**Operator → ChatGPT agent** — Operator preview Jan 23 2025; merged into ChatGPT agent Jul 17 2025; Operator shut down Aug 31 2025; ~40 agent messages/mo Plus, ~400 Pro. Own cloud VM: visual browser (CUA), text browser, terminal, files, spreadsheets, connectors. The most-copied part is the HITL: asks permission before consequential actions; "takeover mode" pauses and hands the browser to the human for credentials/payment with screenshots suspended; interruptible mid-run; "watch mode" on sensitive sites. Session-scoped memory only. Verdict: an acting agent is acceptable exactly insofar as it pauses at consequence boundaries.

**Assistants API → Responses API + Conversations API** — Assistants (persistent server-side assistant objects, beta Nov 2023) deprecated: notice Aug 26 2025, hard sunset Aug 26 2026. Replacement mapping: Assistants → versioned Prompt objects, Threads → server-stored Conversations attached by id, Runs → Responses. A "persistent agent" is now a lightweight composition — prompt object + conversation id + per-call tool array — not a long-lived server entity. Developer consensus: Assistants was slow, opaque, over-stateful; persistence should live in data (conversations, vector stores, prompt versions).

**AgentKit + the "proactive AI" framing** — DevDay Oct 6 2025: Agent Builder (visual multi-agent canvas with routing/handoff edges, guardrail nodes, and first-class human-approval nodes; versioned; exports to Responses/Agents SDK), Connector Registry (admin-governed org catalog of data sources/tools agents draw from), ChatKit. Altman's frame (enterprise event, reported Jun 4 2026): three phases — chat → agents → "constantly running proactive AI", an agent "running in the background all of the time, connected to all my company's context" where users set intentions and the agent batches updates back; named the #1 thing to get ready for, with security redesign + compute as blockers.

Takeaways:

- Memory must be two-layer AND auditable: OpenAI ships an explicit user-editable fact list plus implicit consolidated history, and every major backlash (Willison's "memory dossier" May 2025, Dreaming audit-trail criticism Jun 2026) targets the uninspectable layer. For VF-49: each specialist's memory should be a readable, editable file the user can open — which Voice Flow's file-backed style already favors.
- Scoped isolation is a demanded feature, not a nicety: Projects' per-project memory + per-project instructions that override globals shipped in Aug 2025 because users explicitly asked to fence contexts off. Specialists need their own memory/knowledge silos that don't bleed into each other.
- The proven minimal specialist definition is config, not code: name + instructions + knowledge files + scoped tools + capability toggles (custom GPTs). And the traction is personal/internal specialists (19x enterprise growth, BBVA's 4,000 GPTs), not a marketplace — perfect fit for a single-user app.
- @-mention addressing works: users switch specialists mid-conversation by name while keeping the shared conversation context. The voice analogue for VF-49 is wake-word/name routing onto the same capture stream.
- Proactive output must be a pull-surface digest, never an interruption: Pulse's overnight research → daily card feed with off-by-default connectors and thumbs feedback is the shipped pattern; AI-initiated pinging reads as "obnoxious". This matches Voice Flow's pill-never-takes-the-screen rule exactly.
- Scheduled triggers are table stakes but "notify, don't act" is the acknowledged gap — Tasks can't even run a custom GPT. A specialist that is BOTH scheduled AND empowered to act (with HITL gates) is white space OpenAI itself hasn't closed in the consumer product.
- Offline idle-time consolidation is the state-of-the-art memory mechanism (Dreaming V3, Jun 2026: nightly rewrite of raw fragments into weighted structured memory, auto-revising stale facts, 2x recall at 1/5 compute). Voice Flow's 21:37 watcher review is the same architecture — extend it per-specialist.
- Persistence belongs in data, not in stateful agent objects: the Assistants API (heavy server-side agent entities) is being killed Aug 26 2026 in favor of versioned prompt objects + attachable conversations + per-call tool lists. VF specialists should be files/config + accumulating stores, composed at invocation.
- HITL pattern that survived contact with users: pause-and-handoff at consequence boundaries (agent-mode takeover for credentials, confirm-before-consequential-actions, human-approval nodes as first-class AgentKit primitives).
- Altman's own frame validates VF-49's direction: phase 3 is "constantly running proactive AI" connected to all your context, where the user sets intentions and the agent batches updates back — i.e., persistent named specialists over standing data sources with digest-style reporting.

## 2 · Anthropic ecosystem (Projects, memory, subagents/skills/teams/routines, Cowork, MCP, Agent SDK)

**Claude Code subagents (`.claude/agents/*.md`)** — shipped Jul 2025, GA; the canonical named-specialist mechanism (100+ agent collections on GitHub). A named markdown file: body IS the system prompt (replaces, not appends); YAML frontmatter carries name, description (the routing trigger), tools allowlist / disallowedTools, model pin, optional skills/mcpServers; project/user/plugin/CLI scopes, most-specific wins. Name+description always in context (cheap); body loads on invocation. NO per-agent memory — each invocation is a fresh stateless session; persistence must come from files it reads/writes. Report-back only; no agent-to-agent talk. Complaints (HN Sep 2025): Claude often doesn't invoke the configured agent, token-hungry, "more theatre than utility" when overused; consensus use is read-heavy specialists.

**Agent Skills + plugins** — skills Oct 16 2025; plugins/marketplace Oct 9 2025. A skill = SKILL.md playbook (HOW, not persona) with three-tier progressive disclosure: name+description preloaded (~dozens of tokens), full SKILL.md on match, bundled files on demand. Plugins bundle commands+subagents+hooks+MCP servers, namespaced. Willison, Oct 16 2025: "maybe a bigger deal than MCP" — near-zero authoring cost, dozens of tokens at rest vs MCP's tens of thousands. Community verdict: skills for procedures/knowledge, MCP for live data and side effects.

**CLAUDE.md hierarchy + auto-memory (MEMORY.md)** — CLAUDE.md core since 2025; auto-memory late 2025, default-on. Two plain-file layers: user-authored standing instructions (enterprise → user-global → repo → subdir, @file imports) vs agent-maintained observations (per-git-repo MEMORY.md index, only first ~200 lines / 25KB loaded, overflow in topic files read on demand). Same files load into subagents, teammates, and SDK agents — one memory substrate for every execution form. Recurring complaint is CLAUDE.md bloat (instructions ignored once long) — hence the index+overflow pattern.

**Agent teams (TeammateTool)** — discovered feature-flagged Jan 24 2026, shipped Feb 6 2026 with Opus 4.6; still experimental, disabled by default. Lead spawns named teammates — each a full independent session — coordinated by file-backed primitives: shared task list with file locking + per-agent JSON mailboxes. Teammates addressable by name; user can talk to one directly, bypassing the lead. A teammate can be spawned FROM a subagent definition (same specialist file reused). Tool scoping never severs SendMessage/task tools. HITL is structural: permission prompts bubble to the human; a teammate cannot approve or relay consent; inter-agent messages are marked untrusted by the permission classifier; optional plan-approval mode. Practical consensus: good for parallel research/review, too expensive and flaky for unattended production coding.

**Routines + Cowork scheduled tasks** — Cowork local scheduled tasks early 2026 (run only while the app is open; missed runs queue); routines Apr 14–16 2026, research preview: saved config (prompt + repositories + connectors) executed on Anthropic's cloud on cron/API/webhook/GitHub events, laptop closed, run caps 5–25/day by tier. Per-routine connector/repo selection = per-agent data and tool scope. No one in the loop by design; guardrails are run caps and output surfaces. Received as "cron for agents without the DevOps"; gripes are caps and observability of unattended runs.

**claude.ai Projects + memory** — Projects GA 2024, RAG upgrade 2025; memory Team/Enterprise Aug–Sep 2025 → Pro/Max Oct 2025 → Free Mar 2 2026. Memory is a structured, user-visible and EDITABLE synthesis, scoped PER PROJECT so domains don't cross-contaminate; import from ChatGPT/Gemini. Project knowledge rides fully in context under ~150K tokens, then RAG activates automatically (~10x capacity). Praised specifically for transparency/editability vs ChatGPT's opaque store; reported next step ("Memory Files") converges on the file-based model.

**Claude Cowork** — research preview Jan 2026 → GA Apr 2026; Windows Feb 10 2026; cloud + mobile handoff from Jul 7 2026. General AI coworker on the Claude Code runtime: pick a folder, grant permissions, describe the outcome. Cowork Projects added Mar 2026 — persistent per-project context — because the #1 early complaint was every session starting from zero; shipped within two months of launch. Cloud continuation was the second-most requested.

**MCP** — Nov 2024; OpenAI adopted Mar 2025, then DeepMind/Microsoft/AWS/Salesforce; Linux Foundation Dec 2025; 16,000+ servers. THE attachment layer: tools/resources/prompts discovered at runtime; per-client server allowlists ARE the capability boundary; Mcp-Session-Id gives each client a stable identity (the primitive Voice Flow's session registry is built on). Known gap: server-initiated wake of a disconnected client is not solved — why Voice Flow needs the `vf listen` background-task workaround, and a real constraint for event-triggered assistants. Complaint: token-heavy at startup; deferred tool loading is the mitigation.

**Agent SDK + API memory tool & compaction** — SDK relaunched Sep 2025; memory tool `memory_20250818` beta Aug–Sep 2025, now GA. The contract underneath everything: in-session state accumulates, sessions resumable/forkable, auto-compaction near the limit; across sessions NOTHING carries automatically — persistence is file-based (CLAUDE.md + a client-side /memories directory the model edits with file ops). The API auto-injects: "ALWAYS VIEW YOUR MEMORY DIRECTORY BEFORE DOING ANYTHING ELSE… ASSUME INTERRUPTION: your context window might be reset at any moment, so record progress." Documented multisession pattern: progress log + checklist read at open, updated at close. `canUseTool` callback = programmable human gate; security guidance: path-traversal validation, size caps, expiry sweeps, strip-sensitive-data before writes.

Takeaways:

- A persistent specialist = a definition FILE, not a persistent process. Everything Anthropic shipped converges on: named markdown file (system prompt + tool allowlist + model + description-as-routing-trigger) instantiated as fresh stateless sessions, with all persistence externalized to files the instances read/write. VF-49 assistants should be `~/.config/voice-flow/assistants/<name>/` definitions spawned as ordinary Claude Code sessions over MCP — the mechanism already proven at every scale (subagents, teammates, SDK agents, routines).
- Memory that shipped and stuck is plain, user-editable text with an index-plus-overflow shape — never a vector DB. claude.ai memory is an editable synthesis; auto-memory is a 200-line MEMORY.md index + topic files read on demand; the API memory tool is client-side file ops under /memories with an auto-injected "ASSUME INTERRUPTION — record progress" protocol; consumer memory is moving from one summary to memory files. Per-assistant memory in VF-49 should be a per-assistant directory (index + topic files) that Safet can open and edit — matching his existing SAFET.md/MEMORY.md practice and his reviewable-decisions preference.
- Memory must be scoped per specialist, and users demand it: claude.ai keeps a separate memory per Project explicitly so domains don't cross-contaminate; auto-memory is per-repo; Cowork users forced Projects (persistent per-domain context) into the product within two months of launch because sessions starting from zero was the #1 complaint. Per-assistant memory isolation is validated demand, not speculation.
- Progressive disclosure is THE scaling law of this cluster: name+description always in context, full definition on activation, bundled detail on demand (skills' three tiers, MEMORY.md's 200-line cutoff, Projects' auto-RAG past ~150K tokens, deferred MCP tools). A roster of VF-49 specialists must be nearly free at rest — a picker line per assistant, full prompt+memory loaded only when addressed or triggered.
- Specialty strategy and live data attach differently, and the market punished conflating them: skills (markdown playbooks, ~dozens of tokens) beat MCP for procedures ("bigger deal than MCP" — Willison, Oct 2025) while MCP won as the universal live-data/action layer (Linux Foundation, Dec 2025). Per VF-49 assistant: strategy = a skill-like playbook in the definition; data sources = a scoped list of MCP servers/tools (watcher archive, dictations, Notion, calendar); tool allowlist per assistant with the user-communication channel NEVER scoped out (agent teams keeps SendMessage available even under tool restriction — Voice Flow's report_to_user must be the same).
- Addressing shipped as name-at-spawn + direct talk-to-one-agent: teammates are named and messageable by name, and the user can bypass the lead to talk to a specific teammate (agent panel / split panes). Voice Flow's session picker (⌃⌥1–6, named dots) is already this UI; VF-49 wake-words extend the existing addressing model rather than inventing one — assistants should pre-claim named picker slots the way MCP sessions claim them today.
- Triggers went cloud because local-only scheduling demonstrably failed: Cowork's local scheduled tasks miss runs when the machine sleeps; routines (Apr 2026) moved the same saved prompt+repos+connectors to Anthropic's cloud with cron/API/webhook/GitHub triggers and run caps. Voice Flow's LaunchAgent nightly review is the local pattern already working; VF-49's schedule/event triggers need a daemon-side runner decoupled from the pill UI, with per-assistant run caps and receipts (Safet's own surface-invisible-systems rule).
- Multi-agent coordination that works is file-backed and boring: shared task list with file locking + per-agent JSON mailboxes under ~/.claude/ — the exact architecture Voice Flow already uses for overlays/inbox/pushes. If VF-49 assistants ever need handoffs, mailbox files in ~/.config/voice-flow/ are the proven mechanism; peer-messaging teams remain experimental (Feb 2026, still flagged) and expensive, so default to independent specialists reporting to the user, not an orchestrated swarm.
- HITL boundaries are structural, not prompt-level: permission prompts bubble to the human's session; an agent cannot approve on the user's behalf; inter-agent messages are marked untrusted by the permission classifier; plan-approval mode gates risky work; hooks enforce quality gates with exit codes; unattended routines run capped. VF-49 triggered assistants should run under scoped permissions with asks routed through the existing blocking report_to_user question flow, and inter-assistant input treated as untrusted.
- Reception pattern across the cluster: what users adopted was cheap to author (markdown), transparent (inspectable files, editable memory), and opt-in loaded (progressive disclosure); what stalled was expensive and opaque (token-heavy always-on MCP schemas, over-orchestrated subagent theatre, unattended swarms). VF-49 should bias to few, legible, file-defined specialists over an elaborate runtime.

## 3 · Agent-automation products with real users (Lindy, Zapier Agents, Dust, n8n, Manus)

**Lindy** — shipped, ~$50M+ raised, ~$5M revenue base with claimed ~10x ARR trajectory in 2025; self-serve SMB. An agent = trigger node + NL instructions + action steps on a canvas — deliberately evolved FROM open-ended autonomous agent TO guided workflow with agentic steps (the freeform agent failed in production). Addressed through its connected channels (forward an email to it, Slack it, call its phone number) — the channel binding IS the address. Per-agent tools only (from 1,600+ integrations). Memory: per-agent plain-text "Memories" injected on every run, agent-written, user-editable; team actively prunes because "too many memories confuse agents". Triggers: time / chat / event (Gmail label, Slack, HubSpot, calendar, iMessage, phone, webhook). HITL: "Ask for Confirmation" flag on any side-effectful action (run halts, email + task-view approval), escalation condition steps, Gmail draft-mode. Multi-agent: "Talk with Other Lindy" (explicit call-by-name) + self-cloning Swarms. Telling split: 4.9 G2 vs 1.7 Trustpilot (credit billing: 7 credits/email, 265 per short phone call).

**Zapier Agents** — GA; since 2026 agent steps in regular Zaps are included in normal task pricing. Agent = NL instructions + explicitly granted triggers/actions from the 7,000–9,000 app catalog. Major restructure May 22 2025: "behaviors" abolished — each behavior became its own agent, grouped into "pods"; chat demoted, automation-first. Weakest memory in cluster: no persistent memory between sessions (its most-cited competitive gap). HITL: unified "All Activity" feed across agents with "requires input" states. Multi-month users call narrow-scope agents "really useful".

**Dust** — $40M Series B May 2026; 3,000+ orgs, >90% monthly-active, >70% weekly-active, 240% NRR, 300,000+ agents deployed — the strongest retention evidence in the cluster. Agent = base model + NL instructions + data sources + tools, published to a shared workspace; Pod-level AGENTS.md auto-injected into every conversation's system prompt (May 23 2026). Addressing: `@dust +agentName` in any Slack channel; channel-bound default agents; multiple specialists per thread. Agent Memory (2025) is a TOOL you add: agent decides what to remember, scoped per user × per agent, visible in an inspectable drawer. Context engineering as product: compaction thresholds (30/70/80% — May 6 2026), branching conversations (May 11 2026). Triggers: scheduled agents; "Wake-ups" (Apr 29 2026) — an agent schedules ITSELF to resume the same conversation later and continue where it left off; inbound email auto-routed into the matching conversation (Jun 16 2026). HITL defaults: tool-action approval with a sound only when the user is NOT viewing that conversation (Jul 8 2026); "ask user questions" ON BY DEFAULT for all agents (Jun 30 2026). Friction: Jun 24 2026 switch from flat €29/seat to credit-metered pricing drew backlash.

**n8n AI agents** — valuation $2.5B (Oct 2025) → $5.2B (May 2026); 150K+ GitHub stars, ~200K active users, ~75% of customers use AI features. Agent = AI Agent node in a workflow graph: system prompt + chat model + wired tool nodes + a memory node; nothing available unless wired in. Pluggable memory (window buffer / Redis / Postgres vector) — power and burden on the user; context retention is the top reported struggle (70%+ of automation users). HITL first-class: mark a tool as requiring approval — workflow pauses, sends the request via Slack/Telegram/chat, resumes on approve; docs recommend it for deletes, external comms, purchases. Abandonment driver: everything is on you; non-technical users bounce to Lindy/Zapier.

**Manus** — launched Mar 2025; $100M ARR in ~9 months; acquired by Meta ~$2B Dec 30 2025; China's NDRC ordered the deal unwound Apr 2026. One general autonomous agent in a cloud VM — the counter-example: no named specialists; specialization via user-authored Knowledge entries, Skills, Projects. Knowledge entry format: Name + "When to Use" (NL applicability condition) + Content + on/off toggle — the best-evidenced conditional-context-injection pattern in the cluster. No automatic cross-task preference memory (the manual Knowledge is the patch). Scheduled Tasks fully unattended; Scheduled Tasks 2.0 (2026) continues INSIDE THE SAME TASK with accumulated context instead of re-running cold. HITL front-loaded: clarifying questions at start, then hours of autonomy, notification on completion — no per-action gates. Verdict: "impressive demo, expensive daily driver" (credit burn; $20/mo = 4,000 credits, one complex task can eat most of it).

Takeaways:

- The agent schema converged everywhere adoption is real: NAME + natural-language instructions + explicitly scoped tools (nothing available unless granted) + attached knowledge + triggers. Lindy, Zapier, Dust, and n8n all independently landed on exactly this shape; nothing more exotic survived contact with users. VF-49's assistant definition should be precisely these five fields.
- The trigger taxonomy is settled and small: (1) schedule/cron, (2) app event (email arrives, message posted, webhook, record changed), (3) user-addressed (chat/mention/voice). The one 2026-frontier addition is Dust's "Wake-ups" (Apr 29 2026): the agent schedules ITSELF to resume the same conversation later and continues where it left off — the mechanism that makes an assistant feel persistent rather than re-run.
- Production memory is small, plain-text, per-agent, user-visible, and PRUNED — not a vector database. Lindy injects editable text memories into context on every run and the team actively prunes because "too many memories confuse agents"; Dust scopes memories per user × per agent and shows them in an inspectable drawer; Zapier's LACK of persistent memory is its most-cited competitive gap. For VF-49: a capped, user-editable markdown memory file per assistant is the evidence-backed design.
- Manus's Knowledge entry format is the best shipped pattern for conditional context: Name + "When to Use" (NL applicability condition) + Content + on/off toggle. It maps directly to VF-49's per-assistant data-source and strategy bindings — attach the watcher archive or Notion KB with a "when to use" clause, not as always-on context.
- Human-in-the-loop is the autonomy ENABLER, and the mechanics are uniform: a per-action confirmation flag on side-effectful steps (Lindy "Ask for Confirmation", n8n tool-approval) that pauses the run and notifies through a channel the user already watches; Dust made "pause to ask a clarifying question" the DEFAULT for all agents (Jun 30 2026) and plays a sound only when the user is NOT already viewing the conversation (Jul 8 2026). Voice Flow's report_to_user blocking question + pill receipts is already this exact pattern — VF-49 assistants should route their asks through it per-assistant.
- Reporting home is a persistent activity feed with "needs input" states (Zapier's unified All Activity screen), plus escalation alerts on stuck/out-of-scope conditions (Lindy condition steps: "if outside your scope, alert me on Slack"). Chat-only reporting lost — Zapier explicitly demoted chat in the May 2025 restructure.
- Addressing by name through the surface the user already lives in is the shipped identity mechanism: `@dust +agentName` in Slack, channel-bound default agents, Lindy's channel bindings (forward an email TO the agent). The name is the routing key; VF-49 wake-words are the voice-native equivalent of the @mention, and per-assistant channel/hotkey bindings are the fallback.
- Multi-agent that ships is boring and explicit: grouping (Zapier pods, Dust Pods), one agent calling another BY NAME (Lindy "Talk with Other Lindy"), and self-cloning fan-out (Lindy Swarms). No emergent societies, no autonomous routing. Dust's Pod-level AGENTS.md auto-injected into every conversation's system prompt (May 23 2026) is shipped proof for a shared per-team/per-domain strategy file layered under each specialist.
- One-agent-one-job beat do-everything agents in products with retention: Zapier split every multi-behavior agent into single-purpose agents (May 2025); Dust's 3,000 orgs deployed 300,000+ small agents at >90% monthly-active adoption; Lindy pivoted from open-ended agent to guided single-purpose flows. Manus, the one general-agent counter-example, monetized fastest ($100M ARR in 9 months) but users report no memory of them and reliability limits — validation that a specialist WITH accumulated user context is the retention play, autonomy alone is the demo play.
- The cluster's #1 abandonment driver is unpredictable credit-metered billing (Lindy 1.7 Trustpilot, Manus credit burn, backlash at Dust's Jun 2026 credit switch) — irrelevant to local-first VF, which is itself a differentiator. The #2 is unsupervised reliability, and the products answer it with exactly the trust surface VF already has: visible activity, per-action approvals, editable memory, escalation alerts.

## 4 · Memory / stateful-agent infrastructure (Letta, Zep, mem0, LangGraph, native memory)

**Letta (MemGPT)** — the most-cited reference architecture. Three tiers: CORE MEMORY (small labeled blocks pinned in context — label + description + value + character limit, e.g. "human" and "persona" blocks), RECALL (full conversation history on disk, searchable), ARCHIVAL (explicit long-term knowledge behind retrieval tools); writes are agent-initiated via memory-rewrite tools; the persona block is itself editable memory, not a frozen prompt. Sleep-time compute (Apr 2025): a paired background agent rewrites memory blocks during idle time instead of inline. MAJOR PIVOT Feb 2026, "Context Repositories" (MemFS): memory re-projected as plain git-backed FILES edited with generic bash/file tools instead of specialized DB tools, per-subagent git worktrees for concurrent writers — their own admission that files beat database rows once the agent has computer-use tools.

**Zep (Graphiti)** — commercial memory service + open-source temporal knowledge graph (~20k stars): every extracted fact is an edge carrying validity time (became true / stopped being true / provenance); contradictions resolved by time-scoping the old fact, not deleting it. Writes automatic. Praised for the one thing others lack — knowing when a fact STOPPED being true; graph construction adds ingest latency/cost. Its public benchmark brawl with mem0 (LOCOMO 84% → 58–75% depending on scorer) is the standard citation for "agent-memory leaderboard numbers are marketing artifacts".

**mem0** — largest adoption signal (API calls 35M Q1 → 186M Q3 2025; 41k+ stars; $24M Series A Oct 2025). Drop-in pipeline, not agent tools: extraction (LLM distills facts) → consolidation (ADD/UPDATE/DELETE/NOOP against existing memories) → top-k injection; vector + optional graph + append-only history log as audit trail. Three scopes shipped: user / session / agent — per-assistant memory scoping as a first-class product feature. Complaint pattern: silent automatic extraction gets facts wrong or overgeneralizes and the user never sees the write happen; practitioners say auto-extracted fact quality, not retrieval, is the weak link.

**LangGraph persistence** — de-facto default orchestration persistence. Two deliberately separate layers: checkpointers persist full graph state per thread after every node (continuity, crash resume, time-travel, and the substrate for HITL interrupts — pause mid-graph, wait days, resume from the exact checkpoint), fully automatic; the Store (cross-thread KV/vector) is read/written EXPLICITLY by developer code. Stated doctrine: thread history is structural and automatic; durable memory is "a product decision" the app must own — no auto-extraction shipped. The lesson: nobody trusts a framework to decide WHAT to remember.

**ChatGPT memory (+ Dreaming)** — the largest deployed memory system. Reverse-engineered (shloked.com, 2025) into four buckets bundled into every prompt with no selective retrieval: model set context (the only visible/editable bucket, acting as a patch layer overriding the rest), AI-written "user knowledge memories" (~10 dense paragraphs, NOT visible or editable), recent-conversation log (~40 conversations), interaction metadata. One monolithic profile per account — no per-specialty scoping. Dreaming (Jun 4 2026) = background idle-time curation — OpenAI independently converging on Letta's sleep-time compute. Criticisms: opacity, cross-context leakage (hobby chats coloring work answers), unpredictable injection. OpenAI's bet is explicit: inject everything, trust bigger models to ignore the irrelevant.

**Claude memory + Claude Code file memory** — consumer Claude (Sep 2025): BLANK SLATE + on-demand tools — every chat starts empty; `conversation_search` and `recent_chats` are ordinary visible tool calls over raw past chats, firing only when warranted — zero hidden influence. Team/Enterprise adds a user-viewable, user-editable AI summary scoped PER PROJECT; all plans Mar 2026. Claude Code: memory is literally plain markdown (CLAUDE.md + auto-memory directory) — the same files-convergence as Letta's MemFS. Willison's side-by-side verdict: editable, visible memory resolves the opacity problem ChatGPT has. Complaints: recall requires asking; tool calls add latency.

**Practitioner failure-mode canon** (Adaline Labs / Karpathy / bloo-mind / SitePoint, 2026) — converged guidance: four recurring scopes (user / task / project / operational memory); Karpathy's wiki pattern — memory as structured markdown the agent ingests to, queries before acting, and periodically LINTS for contradictions/staleness; governance triad Remember / Forget / Never-store (credentials, unsupported inferences), every memory carrying owner + scope + expiry + deletion path. Named gap: "hidden influence" — answers shaped by memories the user never saw fire. Memory failures were the most-reported reliability category in 2025 production deployments; the "big context windows kill memory" thesis died in 2025 (mid-context attention degradation).

Takeaways:

- The architecture every shipped system converged on has exactly three parts, and VF-49 assistants should have all three per assistant: (1) a SMALL EDITABLE CORE always in context (Letta memory blocks, ChatGPT model-set-context, Claude project summary — persona + durable facts, hard character cap), (2) a SEARCHABLE RAW ARCHIVE queried on demand via visible tool calls (Letta recall, Claude conversation_search — never auto-injected wholesale), (3) PERIODIC DISTILLED SUMMARIES produced by a background pass. Nothing shipped uses fancy episodic/semantic neuroscience taxonomies; it's context engineering: what tokens are in the window at inference.
- How memories get WRITTEN split into two camps with clear evidence: automatic pipeline extraction (mem0's ADD/UPDATE/DELETE/NOOP, ChatGPT) scales to mass market but produces the top reported failure modes — wrong/overgeneralized facts written silently; agent-initiated edits to visible memory (Letta tools, Claude Code files) are what technical users trust. For a single technical user like Safet: agent-edited plain files, with the automatic pipeline reserved for low-stakes distillation.
- Background consolidation is now independently converged on by three players — Letta sleep-time compute (Apr 2025), Karpathy's periodic lint pass, OpenAI Dreaming (Jun 4 2026): memory maintenance (dedupe, contradiction resolution, staleness expiry, block rewriting) runs on IDLE TIME/schedule, not inline during conversation. Voice Flow already owns this exact pattern (the 21:37 watcher review + ledger.md with 3-sightings/2-days promotion rule) — VF-49 should give each specialist a nightly consolidation pass, not inline memory writes on every turn.
- The 2026 direction for agent-native systems is MEMORY AS PLAIN FILES: Letta rebuilt its whole memory system as git-backed markdown edited with bash (MemFS, Feb 2026) after two years of DB+special-tools, and Claude Code's CLAUDE.md/MEMORY.md pattern is the same design shipped at scale. For VF-49 this is decisive: each named assistant = a directory of markdown memory files (persona block, facts, ledger) under ~/.config/voice-flow/, editable by agent AND user in any editor, versionable, portable across model generations — no vector DB required at one-user scale.
- User visibility/editability is THE differentiator users actually praise: Willison's comparison lands on Claude precisely because retrieval is a visible tool call and the summary is user-editable, while ChatGPT's invisible AI-written "user knowledge" profile is the most-criticized memory feature in deployment. The named failure mode is "hidden influence" — answers shaped by memories the user never saw fire. VF-49: show which memory a specialist used (the pill receipt is a natural surface) and make every memory file openable/editable.
- SCOPE memory per assistant, never account-wide: ChatGPT's monolithic profile causes cross-context leakage; Claude Projects and mem0's user/session/agent scopes shipped isolation as the fix; "wrong-scope memory" is a canonical production failure. Each VF-49 specialist gets its own memory container; sharing between specialists must be an explicit, visible act.
- Keep SESSION STATE and DURABLE MEMORY as separate layers (LangGraph's checkpointer-vs-Store doctrine): transcript/resume state is automatic plumbing; what graduates into long-term memory is a product decision requiring policy — owner, scope, expiry rule, deletion path per memory, plus a Remember/Forget/Never-store governance line (credentials and unsupported inferences never persist).
- Do not pick memory tech from benchmarks: the Zep-vs-mem0 LOCOMO fight (84% → 75% → 58% depending on who scores) and the 2026 "Benchmark Theatre" analysis show every leaderboard number collapses under scrutiny. Choose on failure-mode control and inspectability; at Voice Flow's one-user scale, grep over markdown + a small always-in-context core beats any vector/graph service until proven otherwise.
- Design against the six documented failure modes from day one: stale memory (expiry rules), overgeneralization (one-off instructions must not become preferences — mark scope at write time), wrong-scope leakage (per-assistant directories), memory conflict (explicit user statements are a patch layer that overrides inferred facts — ChatGPT's one universally-liked mechanism), hidden influence (surface retrievals), bad retrieval (fuse multiple retrieval methods only if simple search demonstrably misses).
- Temporal validity is the one capability only Zep ships and the others fake: facts need "became true / stopped being true" timestamps so a specialist doesn't contradict itself when Safet's situation changes (job, priorities, product pivots like Atika). At file scale this is a cheap convention — date-stamped facts with a superseded-by line — not a knowledge graph.

## 5 · Voice assistants with named identities and wake words (+ personal-AI companions)

**Home Assistant Assist (+ Voice Preview Edition)** — open source; Voice PE hardware ($59, Dec 2024) sold out repeatedly. The most complete shipped implementation of multiple named assistants: the wake word IS the router — up to TWO wake words per satellite since HA 2025.10 (Oct 2025), each mapped to its own full pipeline (STT, brain/system-prompt, language, TTS voice). Prebuilt names ("Okay Nabu", "Hey Jarvis") plus fully custom wake words trained in a Colab via openWakeWord (~1 hour, synthetic samples, 3–4 syllables recommended) and dropped in as .tflite; detection server-side or fully on-device (microWakeWord on ESP32-S3). Same house can run one name → fully local deterministic commands AND another → cloud LLM. Tool scoping = explicit per-assistant entity exposure lists (locks/garage not voice-controllable by default); community demanded per-wake-word capability tiers (kid-safe name vs adult name) — requested but unshipped. No persistent per-assistant memory (the acknowledged hole). Triggers: HA automations; 2025.7 "Ask Question" — an automation INITIATES a voice conversation and branches on the answer. Criticism: brittle NLU, setup complexity.

**Amazon Alexa / Alexa+** — Alexa+ in slow Early Access since Mar 2025, repeatedly delayed by hallucination/agentic reliability problems (AGI lead gating release on "hallucinations close to zero"; Reuters, May 2025: six weeks post-rollout, no verifiable Alexa+ users found). Fixed per-device wake-word menu (Alexa, Amazon, Echo, Computer, Ziggy) — all route to the SAME assistant; the name is cosmetic. True named sub-assistants tried twice: celebrity personas with their own wake words ("Hey Samuel", 2019, paid) — killed Jun–Sep 2023 with refunds; "Hey Disney" (2021) still limping in Disney World hotel rooms — the routing worked, the persona economics failed. Routines are the most mature consumer trigger vocabulary: voice phrase, schedule/sunrise, geofence, device state, sound detection (dog bark, baby cry, beeping appliance), plus a developer Custom Triggers API (Sep 2023); Alexa+ adds NL-authored automations.

**Siri + Shortcuts + App Intents** — old Siri stagnant; personalized/memory Siri ("personal context", announced WWDC 2024) officially delayed Mar 7 2025, still unshipped Jul 2026; WWDC Jun 8 2026: Siri AI rebuilt on a custom Gemini model in Apple data centers (~$1B/yr deal), shipping later in 2026. Single identity, single wake word, no alternates ever; the workaround convention: "Hey Siri, <shortcut name>" = named-command routing without a named assistant. App Intents is the cleanest shipped tool-registry model: apps declare typed verbs/nouns as Swift structs, the OS auto-exposes them to Siri/Spotlight/Shortcuts — tools declared by the capability owner and discovered by the assistant. The delay is the data: even Apple could not retrofit persistent personal-context memory onto an existing assistant, and outsourced the brain to a rival.

**Gemini for Home** — shipped and mandatory: Gemini replaced Assistant on ~800M eligible devices (staged from Oct 2025) but the wake word stays "Hey Google" — total brain swap, zero address change. Cross-request context carry-over, multi-intent sentences, voice-authored automations; always-on "Gemini Live" mode paywalled (from $10/mo). Complaints: basic-reliability regressions during the swap. Key precedent: identity continuity beats brain continuity — keep the name, replace everything behind it.

**Dot** — DISCONTINUED Oct 5 2025 (launched iOS Jun 2024; ~24,500 lifetime iOS downloads). One named companion, memory-centric by design: accumulating theory-of-mind, proactive check-ins. Small devoted base praised memory depth; the numbers say memory-persona-as-whole-product found no market. Notable convention: on death, users got a memory export — accumulated context treated as user-owned property.

**Limitless Pendant (ex Rewind AI)** — acquired by Meta (announced Mar 2026), sales ended. No wake word, no name: always-on capture wearable addressed at RETRIEVAL time (chat/search over your recorded life). Capture universally praised ("near-perfect" transcription, strong multi-speaker); retrieval is the documented weakness — "nails frictionless capture but struggles with organization and recall". Exit by acquisition, not user retention.

**Friend pendant** — shipped; culturally radioactive. Always-listening pendant with NO wake word that texts you unprompted comments — it addresses YOU uninvited. Seven-figure NYC subway campaign (Sep 25 2025, 11,000 car cards) met with mass anti-surveillance graffiti; CNN (Nov 16 2025): the device became "a symbol for the backlash against AI". Colleagues asked wearers to disable it in meetings. Demonstrates the hard social constraint on proactive, always-listening named companions.

Takeaways:

- Wake-word → pipeline routing is shipped, proven tech (Home Assistant 2025.10): the name is the router key, and each name binds a complete stack — STT, brain/system-prompt, language, TTS voice, and (requested) permission tier. VF-49's "named specialist = address + config bundle" has exactly one working reference implementation, and it is open source.
- Per-assistant scoping in practice is an explicit allow-list, not inheritance: HA exposes entities per assistant surface with a safety rationale (locks/garage excluded by default), and users independently demanded per-name capability tiers (kid wake word gets lights, adult wake word gets shutters). Specialists should each carry their own explicit tool/data allow-list.
- Persona-as-product died three separate deaths: Alexa celebrity wake-word personas (killed 2023, refunds), Dot (shut down Oct 2025, ~24.5k downloads), Friend (backlash symbol). What survives is named CAPABILITY, not named personality — define specialists by scope + data sources + strategy, keep persona thin.
- Identity continuity beats brain continuity: Google swapped Assistant's entire backend for Gemini across 800M devices but kept "Hey Google"; Apple is putting Gemini inside Siri and keeping "Siri". A name is an address users invest habits in — keep specialist names stable while models/prompts/tools evolve underneath.
- Memory value concentrates at recall, not capture: Limitless was praised for frictionless capture and dinged for "organization and recall", then exited via acquisition. A specialist's accumulating context must be curated and queryable (ledgers, summaries), not a raw archive — and Dot's shutdown export shows users expect that memory to be inspectable/ownable.
- The proactive-trigger vocabulary is already standardized and worth copying: Alexa Routines (voice phrase, schedule, location, device state, sound events, developer custom triggers) + HA automations with the 2025.7 "Ask Question" action where the assistant initiates a voice conversation and branches on the answer. But Friend proves the boundary: proactivity must be user-configured and channel-respectful — uninvited interjection is the documented failure mode.
- Wake-word/name mechanics impose real design constraints: HA caps satellites at 2 wake words, custom names need ~3–4 syllables and an hour of offline training, and detection can run fully on-device (microWakeWord). For VF-49 (routing via existing dictation, not acoustic wake words) the transferable rule is: few, phonetically distinct, stable names.
- Narrow scope is what makes the reliability bar reachable: the do-everything LLM assistants stalled publicly (Alexa+ gated on "hallucinations close to zero" with no verifiable users six weeks post-launch; personalized Siri slipped two years), while tightly-scoped pipelines (HA local commands) ship and work. Specialist assistants with small tool surfaces are the shippable form of the persistent-agent vision Altman is selling.

## 6 · Developer-agent products with persistent specialty configuration

**Devin** — GA, enterprise; best 2026 week = 659 merged Devin PRs internally (vs 154 in 2025); customers report 67% PR merge rate, 20x on security-vuln fixes, coverage 50–60%→80–90%. Two explicit specialty layers: Knowledge — org notes each carrying CONTENT plus a separate TRIGGER DESCRIPTION (semantic recall cue), pinnable to repos (= always injected) or loaded on trigger match, with Devin suggesting new entries for human approval; Playbooks — "a custom system prompt for a repeated task" (steps + success criteria + guardrails in prose), invocable by name (`!triage-bug`) or auto-fired by events (ticket label). Addressing: @Devin in any Slack thread — the thread IS the session (bidirectional sync, unsync to detach); mode keywords (!ultra/!fast/!lite); tagging on Linear/Jira tickets. Scheduled Devins (Mar 20 2026): natural-language schedules Devin sets up itself; runs are incremental — "Devin reads and writes its own notes across sessions" so run N+1 knows where N left off (release notes never re-summarize covered PRs); results post to Slack, not a dashboard. Independent check (Answer.AI, Jan 2025): 3/20 real tasks succeeded, Devin ploughs ahead instead of pausing — Cognition's remedy was exactly the persistent-specialty machinery, turning a 15%-hit-rate generalist into a reliable specialist on scoped recurring work.

**Cursor (rules, Memories, Automations)** — rules are the beloved, copied-everywhere mechanism (.cursor/rules/ per-scope files, alwaysApply vs glob-scoped, plus AGENTS.md; a "best cursor rules" cottage industry). Memories (from v0.51 May 2025): auto-extracted facts with approval-gating on background-generated memories "to preserve trust" — reception mixed-to-poor (invisible, unmanageable, privacy objections; common verdict: implicit memory "still isn't enough", explicit rules do the real work). Automations (Mar 5 2026, expanded Jun 2026): always-on cloud agents fired by schedule OR events (Slack messages/emoji, new Linear issues, merged PRs, PagerDuty, webhooks), each run in a sandbox with that automation's MCPs/models — and the corrected memory design: an explicit Memories TOOL so the agent learns across runs, files deletable/prunable in the UI.

**GitHub Copilot (custom agents, coding agent, Spaces)** — largest scale: 4.7M paid subscribers (Jan 2026, +75% YoY), ~90% of Fortune 100. File-based agent personas: repo-wide and nested AGENTS.md (Aug 28 2025); custom agents (Universe, Oct 28 2025) — a markdown profile with YAML frontmatter (name, description, allowed tools, MCP servers) + system-prompt body in `.github/agents/`; GitHub's own launch example is named specialists @docs-agent / @test-agent / @security-agent. Trigger primitive: assign an issue to Copilot (or a named agent) → background run in Actions → draft PR; Agent HQ (Oct 28 2025) is mission control across vendors. Deliberately stateless per run — persistence lives in files and Copilot Spaces (GA Sep 2025: user-curated, named context bundles). Dominant 2026 gripe: REVIEW BURDEN — PRs land "without a clear trail of what the agent tried, what it validated, or where human judgment is needed". The 2,500-repo AGENTS.md study shows file-encoded conventions are what actually got adopted.

**OpenClaw** — OSS, hyper-viral late Jan 2026 (~180k stars, 20k in one 24h stretch); then a Feb 2026 security crisis. The purest "files are the agent" design: SOUL.md (persona, values, hard limits), AGENTS.md (numbered procedures, memory-logging rules), IDENTITY.md, USER.md (static context card about the human), TOOLS.md; MEMORY.md + memory/YYYY-MM-DD.md daily notes the agent appends itself; HEARTBEAT.md — plain-English cron ("every 30 minutes", "every Monday at 08:00 UTC+8") the runtime interprets. Multi-agent routing via BINDINGS: a channel account (WhatsApp number, Slack workspace) maps to one agent with an isolated workspace — the channel you message IS the address. The crisis: one-click RCE CVE-2026-25253 (CVSS 8.8), poisoned skills on the ClawHub marketplace (17,000+ extensions), ~135k unauthenticated instances exposed, gateway auth off by default. Reception split "this is the future" / "this is a security nightmare" — both are evidence.

**Factory (Droids)** — enterprise; $1.5B valuation Apr 2026 — investors underwriting the named-role-specialist thesis specifically. Product-named role agents: Code Droid, Review Droid, Knowledge Droid (an explicit organizational memory layer feeding the others), Reliability Droid (fires on Sentry signals), under a coordinator architecture; per-droid tools by design; addressed from CLI/web/Slack/Teams/Linear/Jira. Evidence value: a fixed cast of named specialists with per-role tools and a shared knowledge layer is a shippable, fundable architecture.

**Codegen** — smaller player; evidentiary weight is convergence: a third independent company landed on identical addressing mechanics (@codegen in Slack/Linear, ticket = session, Todo → PR merged), and Linear productized "agents as assignees" platform-wide May 20 2025. Persistent sandbox state across runs (installed dependencies survive) — infrastructure persistence rather than knowledge persistence.

**CrewAI (+ AutoGen)** — massive framework usage (claimed ~2B executions trailing 12 months, 27M PyPI downloads) but framework-only; industry reports cite only ~11% of agent initiatives reaching production; 4 CVEs patched in 2026. Agent = role + goal + backstory in YAML/Python compiled into a system prompt. AutoGen entered maintenance mode when Microsoft Agent Framework absorbed it (GA Oct 2 2025, 1.0 Apr 2026) — the role+tool+goal declaration survived, the free-form agent-to-agent chat pattern largely did not. Practitioner consensus by 2026: backstory is prompt seasoning; failures come from delegation loops, token cost, non-determinism — not lack of personality.

Takeaways:

- Specialty is encoded as plain, user-editable files everywhere it works: Devin Playbooks/Knowledge, Copilot agent profiles (`.github/agents/*.md`, YAML frontmatter: name/description/tools/MCPs), Cursor .cursor/rules, OpenClaw SOUL.md/AGENTS.md. "The files are the agent" — portable, diffable, reviewable. VF-49 assistants should each be a folder of markdown (persona, procedures, memory, schedule), not rows in a store.
- Convergent two-layer strategy encoding: a small ALWAYS-LOADED layer (pinned Knowledge, SOUL.md, alwaysApply rules) plus ON-DEMAND procedures retrieved by an explicit trigger description separate from content (Devin's content-vs-trigger split; playbooks invoked by name like `!triage-bug`). "When to recall" must be authored separately from "what to know".
- Addressing has one winning grammar across Devin, Codegen, Copilot, Linear-for-Agents: @name where the user already is, thread = session, reply-in-thread = HITL, bang-command = invoke a named procedure. GitHub shipped literally named specialists (@docs-agent, @test-agent) in Oct 2025. The voice equivalent for VF-49 is wake-word = @mention and a spoken procedure name = playbook invocation.
- Scheduling that sticks (Devin Mar 2026, Cursor Automations Mar–Jun 2026, OpenClaw HEARTBEAT.md): natural-language schedules the agent sets up itself, event triggers alongside cron (Slack emoji, new ticket, merged PR, webhook), and — critically — INCREMENTAL runs: the agent reads/writes its own notes so run N+1 continues from N instead of restarting. Results are always delivered into the human's channel, never parked in a dashboard.
- Implicit auto-derived memory underdelivers; explicit reviewed memory wins. Cursor Memories drew invisibility/trust/privacy complaints and needed approval-gating; Cursor's own fix for Automations was an explicit memory tool with user-prunable files; OpenClaw's MEMORY.md is user-visible by construction; Devin's Knowledge is suggest-then-approve. VF-49 memory must be visible, editable markdown with an approval step for agent-written entries.
- Evidence on scope: persistent specialists earn their keep on bounded, recurring, verifiable workflows (triage, migrations, test coverage, release notes, security fixes — 10–20x claims, 67% PR merge) and fail on open-ended autonomy (Answer.AI 3/20 tasks; Copilot's 2026 review-burden backlash). Each VF-49 specialist should be defined around a recurring workflow with a checkable output, not around a broad domain.
- Persona-only definition is the gimmick end: CrewAI's role/goal/backstory proved to be prompt seasoning, with ~11% of initiatives reaching production; value concentrates in per-agent tool scoping + data-source wiring + procedures. Factory's funded thesis and Copilot's frontmatter both make TOOLS the identity: a specialist IS its tool/data grant plus its procedures; the name and voice are presentation.
- OpenClaw is the decisive demand-and-danger datapoint for exactly the VF-49 shape (persistent named agents, channel-bound addressing, markdown memory, plain-English cron): 180k stars in weeks proves individuals want it; the Feb 2026 RCE/poisoned-skills crisis (135k exposed instances, auth off by default) proves per-agent least-privilege tool grants, default-deny networking, and provenance for third-party skills must be in the spec from day one.

## What this evidence says about failed approaches

The sweep surfaced a consistent set of things that were shipped, funded, and then failed — each one a constraint on the VF-49 spec:

- **The consumer GPT marketplace failed; personal/internal specialists thrived.** The GPT Store was abandoned (pivot to ChatGPT Apps, Oct 2025) and the promised revenue sharing never paid a single developer — while internal specialist usage grew 19x in 2025. People build specialists for THEMSELVES and their org, not to sell. VF-49 needs no sharing/marketplace story.
- **Persona-as-product died everywhere it was tried.** Alexa celebrity wake-word personas: launched 2019 as a paid product, killed Jun–Sep 2023 with refunds. Dot: shut down Oct 5 2025 with ~24.5k lifetime downloads after 15 months. Friend: mass anti-surveillance graffiti on its subway campaign and CNN's "symbol for the backlash against AI". "Hey Disney" limps on in hotel rooms — the wake-word routing worked; the persona economics did not. What survives is named capability (scope + data + tools), with persona kept thin.
- **Heavy server-side persistent-agent objects lost to composed data.** OpenAI's Assistants API — the original stateful Assistant/Thread/Run object model — gets a hard sunset Aug 26 2026, replaced by versioned prompt objects + attachable conversations + per-call tool lists; developer consensus called it slow, opaque, over-stateful. Letta independently abandoned its DB+special-tools memory for git-backed files (Feb 2026). Persistence belongs in data and files, not in long-lived agent entities.
- **Role/goal/backstory is prompt seasoning, not architecture.** CrewAI's signature agent definition ended 2026 with practitioner consensus that the backstory adds nothing (~11% of agent initiatives reach production; failures are delegation loops, token cost, non-determinism); AutoGen's free-form agent-chat pattern did not survive its absorption into Microsoft Agent Framework. The load-bearing parts are per-agent tools, data wiring, and procedures.
- **Invisible auto-memory breeds distrust wherever it ships.** ChatGPT's AI-written "user knowledge" profile is the most-criticized memory feature in deployment (Willison's "memory dossier", May 2025; Dreaming "limits the audit trail", Jun 2026); Cursor Memories drew invisibility/trust/privacy complaints and had to add approval-gating, and Cursor's own Automations redesign switched to an explicit, prunable memory tool; mem0's silent extraction writes wrong/overgeneralized facts the user never sees. "Hidden influence" is the canon-named failure mode. Every trusted implementation is visible, editable, and (for agent-written entries) approval-gated.
- **Credit-metered billing is the #1 abandonment driver in agent products.** Lindy: 4.9 on G2 vs 1.7 on Trustpilot, driven by unpredictable credit burn (265 credits for a short phone call); Manus: "impressive demo, expensive daily driver"; Dust's Jun 24 2026 switch from flat-seat to credits drew immediate negative tracking. (Local-first Voice Flow sidesteps this entirely — a differentiator.)
- **Unattended swarms and open-ended autonomy fail; bounded recurring work succeeds.** Claude Code agent teams remain experimental, expensive, and flaky for unattended coding (leads sometimes do the work themselves); over-orchestrated subagent use reads as "more theatre than utility"; Devin scored 3/20 on open-ended real tasks (Answer.AI, Jan 2025) and became reliable only after Knowledge/Playbooks/scheduling scoped it to recurring verifiable workflows; GitHub Copilot's dominant 2026 complaint is unreviewable PR volume. Independent specialists reporting to the user beat orchestrated swarms.
- **OpenClaw's Feb 2026 crisis defines the security floor.** The exact VF-49 shape — persistent named agents, channel addressing, markdown memory, plain-English cron — went viral (~180k stars) and then produced a one-click RCE (CVE-2026-25253, CVSS 8.8), poisoned marketplace skills, and ~135k unauthenticated internet-exposed instances because auth was off by default and tool access was broad. Per-agent least-privilege tool grants, default-deny, and provenance for anything third-party are non-negotiable spec items, not hardening for later.

## The capability matrix (synthesis pass over all six clusters)

Consensus capabilities — mechanisms MULTIPLE shipped products converge on; the
VF-49 spec adopts all twelve:

   persistent process. Markdown/YAML: name + description (doubles as routing
   trigger) + instructions + tool allowlist + optional model pin; fresh
   stateless sessions at invocation; all persistence externalized to files.

   Lindy/Zapier/Dust/n8n; the Assistants API deprecation proves the inverse.)

   distilled summaries. Never a vector DB at personal scale. (Letta's MemFS
   pivot, CLAUDE.md/MEMORY.md, Lindy, Dust, Manus, OpenClaw.)
3. **Hard memory isolation per specialist**; sharing is an explicit act.
   (ChatGPT Projects, claude.ai per-Project memory, mem0 scopes, Cowork.)

   channel (report_to_user) is never scoped out. (GPT Actions, subagent

   @-mention / wake word / channel binding; few, phonetically distinct names.
   (ChatGPT @-mentions, Home Assistant wake words, @Devin, @dust, "Hey

   (ChatGPT Tasks, Scheduled Devins, Cursor Automations, OpenClaw
